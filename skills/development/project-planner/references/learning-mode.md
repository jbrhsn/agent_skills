# Learn by building

Use when the user requests learning alongside the project. Build a curriculum from the actual implementation units and the learner's starting knowledge; avoid teaching every possible prerequisite before useful work begins.

Use [topics](../assets/topics.template.md) and [learning plan](../assets/learning-plan.template.md) as optional starting points. Small projects can combine them.

Introduce concepts close to first use while allowing earlier foundations when later work depends on them. Cover the relevant mix of language/framework, interface/contracts, testing/debugging, security, and operations. Explain what each concept enables in this project.

For each unit, link needed topics, explain the approach and likely traps, and identify how the learner can demonstrate understanding and verify behavior. Use hints, examples, or code to the degree requested; do not assume that withholding code or forcing a separate build session improves learning.

Link the plan's authoritative acceptance checks instead of copying them by default. If copied for standalone exercises, preserve IDs and update both copies when behavior changes.

Use relevant official documentation matching the project version and verify links when browsing is available. Prefer a few useful resources over a source quota; annotate why a resource is useful when helpful. Mark unverified links or unavailable evidence honestly. Adjust depth from feedback and observed difficulties.
