# Calibration examples

These original examples illustrate clearer teaching, not mandatory prose shapes. Both are constructed for this guide; they are not measurements or reports of learner experience.

## Technical: make a mechanism visible

Weak: “Caching improves performance by storing frequently used data.”

Stronger: “Suppose a page requests the same catalogue twice. A cache keeps the first response and can reuse it for the second request, avoiding a repeated fetch. The trade-off is freshness: if the catalogue changes, the saved response may be stale. Choose when to refresh it according to how much staleness this page can tolerate.”

The stronger version connects the mechanism to a concrete sequence and a decision. A beginner tutorial might trace the two requests; an advanced guide might examine invalidation and concurrent updates. Neither requires an unsupported speedup claim.

## Craft: connect an edit to an effect

Weak: “Start your essay with a compelling hook.”

Stronger: “Compare these invented openings: ‘Our team has communication problems’ and ‘On Monday, three people arrived with three different launch dates.’ The second gives the reader an observable event before naming the general problem. It creates a question the essay can answer: how did the dates diverge? The first may still be better in a brief report whose reader wants the conclusion immediately.”

The stronger version shows an actual revision and explains when each option fits. It teaches a choice without turning a stylistic preference into a universal rule.

## Assessment: separate help from the learner's attempt

A useful practice task might ask the learner to choose a cache-refresh policy for a changing catalogue and justify it. Provide criteria for a good answer. If a solution is requested, add a clearly labelled model answer after the task while leaving any “My attempt” field available for the learner.
