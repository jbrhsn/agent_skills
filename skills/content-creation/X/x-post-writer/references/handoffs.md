# Independent work and optional handoffs

The writer accepts raw notes, inline requests, topics, articles, and drafts directly. It supplies its own format selection, voice inference, source checks, and editorial review. No upstream skill or file is required, and a simple inline request needs no generated metadata files.

## Context in

Use relevant material supplied by the user or clearly associated with the current piece. Do not scan unrelated folders for personal strategy or analytics. File presence alone does not choose X as the platform, and modification time alone does not identify an authoritative draft.

| Optional input | Useful context | Boundary |
|---|---|---|
| `x_strategy.md` or a strategy brief in any format | Audience, purpose, positioning, pillars, voice, editorial constraints | Current user instructions take precedence; surface material conflicts without rewriting the strategy |
| Idea-research output | Angle, audience problem, links, dates, evidence gaps | Popularity and heuristic scores do not establish truth or expected reach |
| `kresearch.md` | Reader vocabulary, entities, discovery intent | Use relevant terms naturally; tags and keyword scores are not mandatory writing targets |
| LinkedIn or Medium draft | Existing argument, evidence, first-person material, useful examples | Adapt within scope; keep the source intact and do not treat every claim as verified |
| Visual plan or media | Proposed composition, caption, intended meaning | Exact visuals need actual assets/data; distinguish provisional alt text from inspected descriptions |

These inputs can be produced by other skills or written by the user. Refer to installed skills by name, never by a repository-specific path. The writer remains usable if none of those skills is installed. An `x_strategy.md` is accepted as user context even when no strategy-producing skill exists.

## Context out

For substantial folder workflows, optional writing notes can record the source/version, audience, purpose, angle or pillar when known, chosen format and rationale, sources and their status, material omissions, account assumptions, count method, and outstanding checks. Include only useful fields; the [notes template](../assets/writing-notes-template.md) is a starting point.

Keep the publishable copy separate from editorial notes. Default names are `x_post.md` with `x_post_notes.md`, or `x_thread.md` with `x_thread_notes.md`. Use distinct descriptive filenames when several requested pieces share a folder. Respect explicit paths, inline delivery, and existing drafts.

A later strategy or research workflow can read these notes to identify follow-up ideas and source gaps. Drafts alone provide no performance evidence: do not invent results or update strategy as if the content had been published. Creating a draft does not automatically trigger another skill.
