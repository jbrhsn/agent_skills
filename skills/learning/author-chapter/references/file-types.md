# File types

These are the standard scaffold's file roles. Follow the requested deliverable and existing brief; filenames help interpret intent but do not prohibit another useful format.

| File | Typical content |
|---|---|
| `learning.md` | Explanations, worked examples, and connections at the requested depth |
| `examples.md` | Attributed specimens or clearly labelled original examples, with annotations |
| `practice.md` | Tasks, success criteria, and optional hints or solutions |
| `interview.md` | Questions, model answers, and useful follow-ups |
| `thought_leadership.md` | Writing angles, supporting evidence, and gaps to investigate |
| `quizzies.md` | Recall, prediction, transfer, or diagnosis questions |

## Answers and learner records

For self-testing, questions before answers usually help. Leave learner response and reflection fields available for their own attempts. When solutions, explanations, or an answer key are requested or useful, provide them separately, after the questions, in collapsible sections, or in a companion file appropriate to the format. Do not refuse answers because of a filename.

Do not invent the learner's attempts, annotations, measurements, experiences, verification, or mastery. A model answer is teaching content, not the learner's record. Clearly labelled hypothetical cases can supply examples without pretending to be personal evidence.

## Adapting each role

For `examples.md`, explain what to notice and why it matters. Published specimens need attribution; original examples need a clear label, not a fabricated source.

For `interview.md`, match the interview or assessment format. Concise spoken answers are useful for oral interviews, while written exams, take-home tasks, and system design can require longer answers. Verify claims about official formats; label original practice questions accordingly.

For `thought_leadership.md`, distinguish evidence already available from evidence still needed. Draft a full article if requested, without claiming experience the learner has not supplied.

When authoring several related files, establish common concepts and scope first. Writing `learning.md` first often helps, but an exercise-led request or existing content may justify another order. Read relevant siblings to maintain consistency without making a complete chapter a prerequisite for a standalone quiz.
