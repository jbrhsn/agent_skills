# Research

Only runs when the user gave no plan, or gave one with agreed gaps. Skip otherwise — do not "improve" a complete plan the user is happy with.

## What to search

Aim for 4–8 searches, in this order of value:

1. **Current role expectations** — job postings for the exact target title and seniority. The most honest source of what's actually tested.
2. **Interview reports** — recent write-ups of loops at comparable companies. Reveals format weighting (how much system design vs coding).
3. **Official docs changelogs** — version-specific features. Training knowledge goes stale here fastest.
4. **Established roadmaps/curricula** — use as a checklist against your draft, not as the draft.
5. **Ecosystem shifts in the last 12 months** — tools that replaced what you'd otherwise include.

## Weighting

- Job postings and recent primary docs > blog roadmaps > aggregator listicles.
- If two sources disagree on whether a topic still matters, include it as a chapter and note the contention in PLAN.md.
- Never cite a source inside a stub file. Sources belong in PLAN.md only.

## Output of this step

A short bullet list of **what research changed** about your draft — topics added, dropped, or reordered, with one-line reasons. Show this to the user alongside the plan. If research changed nothing, say so plainly.
